# Concurrency Model & Thread Safety Architecture

This document explicitly defines the concurrency boundaries, ownership rules, and thread synchronization invariants of the Minecraft Journal engine (P13.4).

---

## 1. Thread Domain Architecture

| Engine Subsystem | Execution Thread | Permitted Operations | Concurrency Guarantees |
|---|---|---|---|
| **World Simulation** | **Main / Game Thread** (20 TPS fixed authoritative tick) | Player kinematics, collision resolution, block breaking/placement, item throwing, fluid update dispatch. | Authoritative single-writer. Synchronously drives gameplay state without race conditions. |
| **Terrain Generation** | **Asynchronous Worker Pool** (`ChunkWorker-1..N`) | Continental noise evaluation, cave noise, 3D voxel population, POI structure insertion. | Fully parallel. Workers operate on isolated, newly instantiated `Chunk` objects before publishing. |
| **Greedy Meshing** | **Asynchronous Worker Pool** (`ChunkWorker-1..N`) | 2D Face merging, quad reduction, Ambient Occlusion corner calculations, 3x3 `ChunkNeighborhood` traversal. | Workers read chunk state arrays via immutable snapshots or thread-safe maps, producing detached `MeshData`. |
| **GPU Upload & Draw** | **Render Thread** (Main Thread with active OpenGL context) | VAO/VBO/EBO allocation and buffer streaming, texture binding, shader uniforms, multi-pass rendering. | **Strictly thread-affine**. Only the Render Thread is permitted to invoke OpenGL API calls (`gl*`). |
| **World Persistence** | **Dedicated I/O Worker** (`WorldSave-Worker`) | Binary paletted serialization, region file sector allocation, `world.jmc` metadata persistence. | Non-blocking background persistence. Takes non-blocking in-memory state snapshots. |

## 2. Thread Synchronization Invariants

### 2.1 Chunk Lifecycle Transitions
Chunks transition through an explicit lifecycle managed by `ChunkStatus`:
```text
UNLOADED → QUEUED → GENERATING → GENERATED → MESHING → MESHED → GPU_LOADED
                                                                      ↓
                                            UNLOADED ← GPU_UNLOADED ← UNLOAD_QUEUED
```
- Thread-safe state transitions are mediated by atomic operations on `ConcurrentHashMap<ChunkPos, ChunkStatus>`.
- Redundant generation tasks are pruned early if a player moves out of render distance before a worker executes the task.

### 2.2 OpenGL Thread Affinity
- Under GLFW and OpenGL 3.3 specifications, OpenGL contexts are tied strictly to the thread that invoked `glfwMakeContextCurrent()`.
- Background worker threads **never** allocate GPU buffers or call OpenGL methods.
- Meshes generated by worker threads are handed off via `ChunkUploadQueue` and consumed by the Render Thread within strict per-frame upload budgets (`maxUploadsPerFrame` and `maxBytesPerFrame`) to eliminate frame stutter.

### 2.3 World Mutations & Fluid Batching
- Mutations from player interactions or explosions mark chunks in a thread-safe `DirtyChunkSet`.
- `FluidPhysicsManager` buffers mutations in a temporary `mutationBuffer` during fluid evaluation, then applies them atomically to `ChunkManager` before triggering deduplicated mesh rebuilds.
